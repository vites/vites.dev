Mainframe · REST

Integrar un core asegurador Mainframe con servicios REST

Definir el contrato a partir del proceso

Una consulta de póliza y una operación que modifica una póliza tienen necesidades distintas. Define entradas, salidas y errores de negocio. Mantén la representación del API estable aunque cambien los formatos internos del Host.

Decidir qué ocurre si se pierde una respuesta

Si una escritura se confirma en el Host pero la respuesta se pierde, un reintento puede duplicar la operación. Diseña una clave de idempotencia y guarda su resultado de forma consistente con el cambio de negocio. Usa un identificador de correlación para seguir la petición entre sistemas.

Probar con datos ficticios

Incluye casos de timeout, reintento, caída parcial y petición duplicada. Verifica el estado que queda en ambos extremos y comprueba que los registros de diagnóstico permiten reconstruir la operación sin contener datos personales ni credenciales.
